# Как следить за ходом выполнения задач

Сводка-инструкция по командам для владельца проекта. Всё, что нужно,
чтобы контролировать прогресс по задачам из `TASKS.md` и журналу `PROGRESS.md`.

> Всего задач — **37**. Для точного счёта в командах используется якорь
> `^### [ ]`, чтобы считать **только** заголовки задач, а не упоминания
> `[x]`/`[~]` в легенде и правилах в самом файле.

## Первый шаг (setup, один раз)

1. **Закрепить 4 process-файла в `main`** (они про проект в целом, не про реализацию):
   ```bash
   git add TASKS.md PROGRESS.md TRACKING.md DECISIONS.md
   git commit -m "docs(tracking): add task/process files"
   ```
2. **Создать ветку переписывания** (см. `DECISIONS.md`, раздел «Git-процесс»):
   ```bash
   git checkout -b feat/rewrite-angular-signals
   ```
   Агент делает **1 commit на задачу** в этой ветке; `main` остаётся «legacy + spec»
   как эталон. Вся история переписывания — по команде `git log --all --oneline --grep='task'`.


## Быстрый старт (3 команды)

```bash
# Сколько задач сделано из общего числа (37)
grep -c '^### \[x\]' TASKS.md

# Что уже закрыто
grep -n '^### \[x\]' TASKS.md

# Что впереди (в работе / не начато)
grep -n '^### \[~\]\|^### \[ \]' TASKS.md
```

## Обзор статусами

| Что хочу узнать | Команда |
|---|---|
| Весь список со статусами (один экран) | `grep -n '^### \[' TASKS.md` |
| Сколько сделано из всех | `echo "$(grep -c '^### \[x\]' TASKS.md) / 37"` |
| Что сделано | `grep -n '^### \[x\]' TASKS.md` |
| Что не начато | `grep -n '^### \[ \]' TASKS.md` |
| Что в работе (агент сейчас в этом) | `grep -n '^### \[~\]' TASKS.md` |
| Прогресс в процентах | `echo \"$(( $(grep -c '^### \[x\]' TASKS.md) * 100 / 37 ))%\"` |

## Что делает агент и как это проверить надёжно

Каждая задача = **чекбокс `[x]`** в `TASKS.md` + блок `> **Выполнено:**` +
**1 git-коммит** + запись в `PROGRESS.md`. Скрестируйте:

```bash
# 1) Задача помечена [x]
grep -n '^### \[x\] 2\.4' TASKS.md

# 2) Есть ли коммит под эту задачу (по conventional-сообщению, по всем веткам)
git log --all --oneline --grep='task 2.4'

# 3) Есть ли запись в журнале
grep -n '2\.4' PROGRESS.md
```

Если все три пункта есть — задача реально закрыта и проверена.

## Порядок, в котором идти дальше

Задачи нумерованы по фазам (Фаза 0 → 8). Ближайшая к исполнению — первая
`[ ]` по порядку сверху вниз:

```bash
# первая не начатая задача
grep -n '^### \[ \]' TASKS.md | head -1
```

Первым делом — Фаза 0: **0.1** (стек Angular 19+ / Taiga UI v5, PWA),
**0.2** (тесты/билд), **0.3** (подключить AI-интеграцию Taiga UI —
MCP `@taiga-ui/mcp` + `llms.txt`), иначе UI-задачи (3.3, 5.3, 5.4,
6.x, 8.x) будут выполняться вслепую.

## История вне git

Файл `PROGRESS.md` (append-only) содержит журнал всех сессий агентов:
дата, выполненная задача, что сделано, как проверено, коммиты.

```bash
# весь журнал
cat PROGRESS.md

# последние 2 записи (в конце файла)
tail -n 40 PROGRESS.md
```

## Подсказка по коммитам

Агент оформляет 1 коммит на задачу с conventional-сообщением, например:

```
feat(race-lifecycle): implement task 2.4 start/pause/reset
```

Поэтому всю историю реализации видно одной командой:

```bash
# по всем веткам (main и feature-ветка переписывания)
git log --all --oneline --grep='task'
```

## Промпты для 3 ролей (когда запускать и что писать)

Каждая роль — отдельный запуск агента в Pi **или** OpenCode (см. `DECISIONS.md` § «Роли и конвейер»).
Передача хода — за **тимлидом** (человек). Порядок: **1 → 2 → 3 → (2)** → приёмка.

### 1) Тимлид — `qwen3.8:27b-mlx` (Pi, как сейчас)

```text
Я тимлид проекта BeClocked. Задача <N.M> из TASKS.md. Прочитай её «бюджет чита»,
сформулируй промпт для реализатора (Recursive Flint) и для ревьюера
(nemotron-3.5-lightning:30b-mlx). Переведи статус задачи на `[~]`,
приготовь блок «Выполнено» под заполнение после ревью.
```

### 2) Реализатор — `Recursive Flint` (Pi или OpenCode)

```text
Реализуй задачу <N.M> из TASKS.md. Стек: Angular 19+, standalone, signals, zoneless.
Логика — из legacy src/app/** (эталон), код — сигналы/standalone (RxJS убрать).
Taiga UI — по актуальному API (@taiga-ui/mcp / llms.txt), не из памяти.
Держись строго в одном Requirement из openspec/specs/**. 1 commit, ветка
feat/rewrite-angular-signals. Вставь заполненный блок «Выполнено» под задачу.
```

### 3) Ревьюер — `nemotron-3.5-lightning:30b-mlx` (Pi или OpenCode)

```text
Сревьюируй commit <sha> для задачи <N.M> из TASKS.md по 5 критериям из
DECISIONS.md → «Критерии ревью»: (1) чек-лист приёмки, (2) строго один Requirement,
(3) нет RxJS — только signals/standalone, (4) Taiga UI по актуальному API, (5)
1 commit = 1 задача в feature-ветке `feat/rewrite-angular-signals`. Выдай вердикт: Approved или
«changes requested» со списком конкретных замечаний (файл + строки + что заменить).
```

## Приёмка задачи (тимлид делает это)

После вердикта `Approved`:

1. Перевести заголовок задачи `[~] → [x]` в `TASKS.md`.
2. Заполнить блок `> **Выполнено:**` (с ролью + вердиктом + commit).
3. Досписать запись в `PROGRESS.md` (append-only).

При `changes requested` — вернуть на шаг 2 (Реализатор) в том же commit,
ревьюер смотрит снова до `Approved`. 1 задача = 1 commit = 1 Approved = 1 приёмка.
