# Race Lifecycle Specification

## Purpose

Определяет жизненный цикл гонки: её типы, состояния, переключение между ними,
именование, запуск/остановку/паузу и сброс, а также обнаружение незавершённой
гонки при запуске приложения.

## Requirements

### Requirement: Тип гонки

SHALL Система поддерживает два типа гонки — `Разделка` (ITT) и `Групповая` (GROUP).
По умолчанию используется тип `Разделка`. Изменить тип можно до начала гонки;
после начала или завершения гонки переключение типа блокируется.

#### Scenario: Выбор типа до старта

- GIVEN гонка ещё не начата
- WHEN пользователь выбирает один из двух типов
- THEN гонка переходит на выбранный тип управления и отображения

#### Scenario: Блокировка переключения после старта

- GIVEN гонка запущена (или завершена)
- WHEN пользователь смотрит на переключатель типа
- THEN переключатель заблокирован и показывает текущий тип

### Requirement: Имя гонки

SHALL Гонка имеет наименование. По умолчанию используется значение
`Название гонки`. Имя можно изменить перед началом гонки; во время гонки
имя отображается как заголовок и не редактируется.

#### Scenario: Имя по умолчанию

- GIVEN новая гонка без сохранённого имени
- WHEN гонка инициализируется
- THEN отображается имя `Название гонки`

#### Scenario: Изменение имени

- GIVEN пользователь перед стартом редактирует имя
- WHEN пользователь сохраняет непустое значение
- THEN новое имя сохраняется и отображается как заголовок гонки

### Requirement: Состояния гонки

SHALL Жизненный цикл гонки проходит состояния: подготовка (`PREPARE`), готовности
(`READY`, список участников добавлен), проведения (`START`), паузы
(`PAUSE`) и завершения (`FINISH`).

#### Scenario: Переход в состояние готовности

- GIVEN в состоянии `PREPARE`
- WHEN в список добавляется первый участник
- THEN переход в состояние `READY`

### Requirement: Обнаружение незавершённой гонки

SHALL При запуске приложения система проверяет наличие сохранённой незавершённой
гонки. Если она найдена, пользователю предлагается продолжить её или начать
новую; новая гонка очищает сохранённое состояние.

#### Scenario: Предложение продолжить

- GIVEN в хранилище есть сохранённая гонка со списком участников
- WHEN приложение запускается
- THEN отображается диалог с выбором «Продолжить» или «Новая гонка»

#### Scenario: Отсутствие сохранённой гонки

- GIVEN сохранённая гонка отсутствует
- WHEN приложение запускается
- THEN хранилище очищается и создаётся новая гонка

### Requirement: Завершение гонки

SHALL Гонка помечается завершённой по явному действию или автоматически, когда все
участники получили статус Финиш или DNS. При завершении фиксируется время
завершения.

#### Scenario: Автоматическое завершение

- GIVEN все участники имеют статус Финиш или DNS
- WHEN это условие становится истинным
- THEN гонка завершается автоматически, фиксируется время завершения

### Requirement: Сброс гонки

SHALL Пользователь может сбросить гонку в любое время; сброс очищает сохранённое
состояние и возвращает систему в состояние `PREPARE` с настройками по
умолчанию.

#### Scenario: Сброс с подтверждением

- GIVEN запущена или начата гонка
- WHEN пользователь подтверждает сброс
- THEN состояние очищается и система возвращается в `PREPARE`
