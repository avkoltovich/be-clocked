# Racer Management Specification

## Purpose

Определяет управление списком участников гонки: добавление, редактирование,
удаление, изменение порядка, присвоение стартовых номеров, работу с
категориями и проверку полноты номеров перед стартом.

## Requirements

### Requirement: Модель участника

SHALL Участник описывается именем, категорией, стартовым номером (необязательным) и
статусом. Новому участнику присваивается статус готовности (`READY`).

#### Scenario: Поля участника

- GIVEN создаётся новый участник
- WHEN указываются имя и категория
- THEN стартовый номер может отсутствовать, а статус по умолчанию `READY`

### Requirement: Добавление участника

SHALL Участника можно добавить вручную с именем, номером, категорией и опциональным
порядком вступления. Если указан порядок вступления (`startNumber`), участник
вставляется на эту позицию, в ином случае добавляется в конец списка.

#### Scenario: Добавление в конец списка

- GIVEN указан участник без порядка вступления
- WHEN участник добавлен
- THEN он оказывается в конце списка участников

#### Scenario: Вставка в позицию

- GIVEN указан порядок вступления
- WHEN участник добавлен
- THEN он вставляется на указанную позицию списка

### Requirement: Изменение порядка

SHALL Порядок участников можно изменять перемещением вверх/вниз. В режиме `Разделка`
перемещение доступно лишь для участников с индексом не меньше текущего стартовав
индекса; в режиме `Групповая` — когда гонка ещё не начата и не завершена.

#### Scenario: Перемещение участника в Разделке

- GIVEN режим `Разделка` и гонка идёт
- WHEN пользователь перемещает участника, не достигнутый стартом
- THEN порядок списка обновляется

### Requirement: Присвоение стартового номера

SHALL Номер участнику можно присвоить отдельно через диалог. Присвоить номер,
который уже занят другим участником, невозможно — система показывает
предупреждение и блокирует сохранение.

#### Scenario: Уникальность номера

- GIVEN номер уже присвоен другому участнику
- WHEN пользователь вводит этот номер
- THEN отображается предупреждение «Номер занят» и сохранение заблокировано

#### Scenario: Успешное присвоение

- GIVEN свободный номер
- WHEN пользователь вводит его через диалог
- THEN номер присваивается участнику и сохраняется

### Requirement: Категории участников

SHALL Участники группируются по категориям через карту категорий. Категорию можно
добавить новую. Изменения списка участников синхронизируются с картой
категорий (при удалении/редактировании участник удаляется из категории).

#### Scenario: Синхронизация с категорией

- GIVEN участник принадлежит категории
- WHEN участник удаляется или редактируется
- THEN карта категорий обновляется соответствующим образом

### Requirement: Полнота номеров

SHALL Система отслеживает, все ли участники имеют стартовый номер. Если хотя бы один
участник без номера, стартовая панель показывает ошибку и не даёт начать
гонку.

#### Scenario: Отсутствуют номера

- GIVEN есть хотя бы один участник без номера
- WHEN пользователь смотрит на стартовую панель
- THEN отображается ошибка «Не у всех участников заполнены номера», и кнопка старта заблокирована

### Requirement: Нормализация названий категорий

SHALL При импорте участников определённые длинные регистрации катигорий
сокращаются: значения-заготовки с «Шоссе (групповой велосипед)» становятся
«Шоссе», а «Шоссе (разделочник или групповой с лежаком)» — «Шоссе ТТ».

#### Scenario: Нормализация импортированной категории

- GIVEN импортированный участник с категорией «Шоссе (групповой велосипед)»
- WHEN выполняется импорт
- THEN участник получает категорию «Шоссе»
